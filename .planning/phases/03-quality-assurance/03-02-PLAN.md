**Window Filtering Fix (D-06 through D-11):**

In `WindowEnumerationService.swift`, modify `parseWindowInfo()`:

1. Keep `layer == 0` check but add documented exceptions per D-07. Change the guard to:
```swift
// Layer 0 = normal windows. Allow layer exceptions for known valid cases.
guard let layer = info[kCGWindowLayer as String] as? Int,
      layer == 0 else { return nil }
```
(Layer 0 is correct — the real issue is the `optionOnScreenOnly` flag in `enumerateWindows()`, not the layer filter.)

2. Keep `w > 0, h > 0` filter per D-08.

3. Fix the REAL filtering issue per D-09: The `CGWindowListCopyWindowInfo` call on line 21 uses `.optionOnScreenOnly` which excludes minimized windows. This is correct because minimized windows are already handled separately via the AX path (lines 33-55). The 68% filtering is actually expected — most CGWindowList entries are system windows (menubar, dock, status items, etc.) that correctly get filtered by `layer == 0`. The fix is to ensure the AX minimized path works correctly and to NOT double-filter.

4. Add debug logging per D-10 — add an NSLog in `parseWindowInfo` for filtered-out windows:
```swift
private func parseWindowInfo(_ info: [String: Any], isMinimized: Bool) -> WindowInfo? {
    guard let windowID = info[kCGWindowNumber as String] as? CGWindowID,
          let ownerPID = info[kCGWindowOwnerPID as String] as? pid_t,
          let ownerName = info[kCGWindowOwnerName as String] as? String else {
        return nil
    }

    guard let layer = info[kCGWindowLayer as String] as? Int, layer == 0 else {
        NSLog("WindowEnum: Filtered windowID=\(info[kCGWindowNumber as String] as? CGWindowID ?? 0) owner=\(ownerName) reason=layer(\(info[kCGWindowLayer as String] as? Int ?? -1))")
        return nil
    }

    guard let boundsDict = info[kCGWindowBounds as String] as? [String: CGFloat],
          let x = boundsDict["X"], let y = boundsDict["Y"],
          let w = boundsDict["Width"], let h = boundsDict["Height"],
          w > 0, h > 0 else {
        NSLog("WindowEnum: Filtered windowID=\(windowID) owner=\(ownerName) reason=bounds")
        return nil
    }
    // ... rest unchanged
}
```

5. Also in `enumerateWindows()`, remove the self-filtering by bundleID (line 59 uses string comparison "AltTab" which is fragile). Replace with PID-only check:

**Hotkey Thread Safety (D-28):**

In `HotkeyManager.swift`, add a serial DispatchQueue for state synchronization:

1. Add property: `private let serialQueue = DispatchQueue(label: "com.alttab.hotkey-state")`

2. Wrap all `state` reads/writes in `serialQueue.sync { }`. The `handleEvent` method is called from the CGEvent tap callback (potentially background thread). All state transitions must go through the serial queue:

```swift
fileprivate func handleEvent(_ proxy: CGEventTapProxy, type: CGEventType, event: CGEvent) -> Unmanaged<CGEvent>? {
    if type == .tapDisabledByTimeout || type == .tapDisabledByUserInput {
        if let tap = eventTap {
            CGEvent.tapEnable(tap: tap, enable: true)
        }
        serialQueue.sync {
            if state == .active {
                state = .idle
                DispatchQueue.main.async { [weak self] in
                    self?.delegate?.hotkeyDidCancel()
                }
            }
        }
        return Unmanaged.passUnretained(event)
    }
    // ... rest of method wraps state access in serialQueue.sync
}
```

3. Similarly wrap the `startReEnablePolling` timer's state check (line 146) in `serialQueue.sync`.

4. In `handleFlagsChanged` and `handleKeyDown`, wrap the `switch state` blocks in `serialQueue.sync`. Since these return values, use `serialQueue.sync { -> Unmanaged<CGEvent>? in ... }`.
